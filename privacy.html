Privacy Policy — Yui-Chan

Applies to the internal automation app Yui-Chan (Google Cloud project yui-chan-497118).
Effective date: 16 October 2026 · Last updated: 16 October 2026

1. Who this app belongs to

Yui-Chan is a private, single-user automation app operated by Geoffery Powell for his own Google Account. It is not offered to the public, it has no other users, and no other person's Google data is ever requested or accessed. Because it is used by exactly one person, the "user" and the "operator" in this policy are the same individual.

Contact for any question about this policy or the app's data handling: powellgeoffery@gmail.com.

2. What Google data the app requests, and why

The app requests the following permissions when the account owner connects it. Each one exists to carry out a request the owner makes, and nothing else:

  • View calendar events (calendar.readonly) — so it can answer the owner's questions about their own schedule: what is coming up, whether a given time is free, when a particular appointment is.
  • View and edit calendar events (calendar.events) — so it can create, change, move, respond to, or delete events when the owner asks it to.
  • Read email (gmail.readonly) — so it can find and summarise messages the owner asks about, such as locating a receipt or reading an unread thread. The app cannot send, draft, label, archive, trash or delete mail: it does not hold the permissions those actions require.
  • Manage files in Google Drive (drive) — so it can find, read, download, create, rename, move, share and delete the owner's own files and folders when asked. Deletions always require the owner's explicit confirmation first (see section 7).
  • Read and edit Google Docs, Sheets and Slides (documents, spreadsheets, presentations) — so it can read the content of the owner's documents and change it at their request.

Google Tasks is reached through the owner's own separate automation, not through this credential.

It does not request permission to create, delete, rename, or change the sharing settings of a calendar. Those operations are outside the permissions granted and are technically unavailable to the app. It does not read Google Contacts, Google Photos, or any other Google product, and no data is collected about anyone other than the account owner.

3. How Google data is used

Google data is used for exactly two purposes, both initiated by the account owner:

  • reading the owner's own calendar events, email and files back to the owner, in answer to a question;
  • creating or modifying an event, document, spreadsheet, slide deck, folder or file in the owner's own Google account, at their request.

Google data is never used for advertising, profiling, credit or lending decisions, or any purpose unrelated to showing and editing the owner's schedule. No Google user data is used to train or improve artificial-intelligence models, by the operator or by anyone else.

4. Where the data lives, and for how long

  • Access tokens. The OAuth token that authorises the app is stored in a permission-restricted file (0600) on the owner's own self-hosted server. It is never transmitted anywhere except to Google's own API endpoints.
  • Calendar content. Event data is fetched on demand and is not copied into any database, index, or backup. Nothing is retained after the request finishes.
  • Write log. The app keeps a local plain-text log of changes it makes (timestamp, action, which calendar or file, object identifier, object name) so the owner can audit what was changed on their behalf. It contains no data belonging to anyone else and lives only on the owner's server. It can be deleted at any time on request.

5. Sharing, transfer, and third parties

Google user data is not sold, rented, traded, or shared with any third party, and it is not transferred to anyone for advertising, marketing, or data-brokerage purposes. The app has no analytics, no telemetry, and no advertising components.

One narrow disclosure: requests to this app are handled by an AI assistant. To answer the owner's question or carry out the requested change, the relevant content — for example email text, a document or an event — may be processed by the large-language-model provider the owner has configured for the assistant, under that provider's standard API terms. This processing happens solely to fulfil the owner's own request, on the owner's own data, and is limited to the minimum content needed to complete it.

6. Google API Services User Data Policy

Yui-Chan's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

7. Your control over the data

  • Revoke access at any time at myaccount.google.com/permissions, or from the Google Account's third-party apps page. Revocation takes effect immediately; the app's credential stops working and the stored token can then be deleted.
  • Delete the local credential by removing the token file on the owner's server, which immediately ends the app's access.
  • Request deletion of the local write log by emailing the contact address above.
  • Nothing is ever deleted without confirmation. The app only deletes a calendar event or a Drive file when the account owner has explicitly confirmed that specific item, and every deletion is recorded in the write log described above. Email cannot be modified or deleted at all.

8. Security

Credentials are stored with owner-only file permissions on a self-hosted server behind the owner's own network, and are sent only over TLS to Google's endpoints. The OAuth grant is deliberately scoped to the two Calendar permissions listed in section 2 rather than to broad account access.

9. Children

The app is not directed at children and is not used by anyone under 13. It has no users other than its owner.

10. Changes to this policy

Any change to how the app handles Google user data will be reflected on this page with a new "last updated" date.
